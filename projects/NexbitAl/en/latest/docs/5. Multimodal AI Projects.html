5.1 Multimodal AI Network Configuration & Device Binding ​

5.1.1 Module Network Configuration ​

  1. Power on the device. For first-time use, the Multimodal AI module must be connected to the network first. At this time, the screen displays the device hotspot name and the browser configuration URL alongside voice broadcast prompts. The module automatically activates its built-in Wi-Fi hotspot for configuration. Each device has a unique hotspot name following the Robot-xxxx format. The following steps use hotspot Robot-B7B9 as an example.
  1. Search for the corresponding hotspot using a computer or mobile phone and connect. The hotspot requires no password.
  1. Click Network Configuration to access the device configuration page directly, or copy the URL below into any web browser:
py
http://192.168.3.1
  1. Enter the Wi-Fi hotspot name to connect automatically upon power-up in field ①, and enter the Wi-Fi password in field ②. Click Connect in field ③. The module will search for the matching hotspot in the current environment and connect based on the provided credentials.
  1. If the following prompt appears, the hotspot cannot be found in the current environment or the password is incorrect. Please re-enter the credentials.
  1. If the following prompt appears, the module has located the hotspot and connected successfully. The module restarts automatically and connects to the designated hotspot.
  1. After completing network configuration, bind the module to a platform agent. The module screen displays the 6-digit device ID and the device binding website URL while broadcasting the binding verification code. Bind the module device to the platform. The string XXXXXX beneath the binding URL represents the device ID.

5.2.6 Q&A ​

Question 1: What is MCP?

Answer: MCP, also known as Model Context Protocol, is a tool-calling configuration mechanism. It defines hardware feature tools available to the AI module, specifying tool names, functional descriptions, and input parameter formats. This mechanism enables large language models to interpret voice commands and output parameters in an agreed format, allowing the underlying hardware to execute corresponding actions.

Question 2: Why configure MCP?

Answer: Large language models cannot directly manipulate hardware. Configuring MCP tools informs the AI module of available hardware features and parameter structures. This enables the AI to convert parsed voice semantics into executable command parameters recognized by the hardware, achieving AI voice control over physical devices.

Question 3: What happens if MCP is not configured?

Answer: Without MCP configuration, the AI module cannot identify available dot matrix display tools. It cannot parse voice commands or generate corresponding control parameters. Even if speech is recognized, the micro:bit dot matrix screen cannot be driven, preventing voice-controlled display features from functioning.

5.3.6 Q&A ​

Question 1: With two sets of MCP tools configured in this project, can the AI invoke both tools simultaneously?

Answer: Yes. MCP supports invoking multiple tools concurrently following a single semantic interpretation. Based on voice semantics, the AI populates parameters for both the microbit_music and rgb_color tools. The controller executes lighting changes and music playback in parallel, achieving synchronized sound and light interaction.

Question 2: What does setting an MCP tool to non-blocking (false) signify?

Answer: Non-blocking signifies that after a tool is called, the program does not wait for hardware actions to finish before continuing execution. It immediately returns to the main loop to continue listening for voice commands. Even during long musical playback, new voice commands can be received and processed.

Question 1: In the ultrasonic lighting MCP tools, how does the definition of RGB parameters differ between static color mode and breathing mode?

In breathing light mode, red, green, and blue no longer indicate brightness. Instead, they define the fading transition duration in seconds for each color channel across a range of 0 to 10. Question 2: What lighting effect is produced when breathing light parameters are set to red=2, green=0, and blue=0?

5.8.6 Q&A ​

Question 1: Can drive_mode be set to 1 and 2 simultaneously to enable following and obstacle avoidance at the same time?

Answer: No. Only one autonomous driving mode can be enabled at a time. If two modes are enabled simultaneously, sensor control logic will conflict, causing abnormal movement of the robot car.

Question 2: After obstacle avoidance mode is enabled, who controls the autonomous motion of the robot car, and does the AI still need to issue continuous motor commands?

Answer: The autonomous motion of the robot car is controlled locally in real time by the micro:bit controller, which reads sensor data. The AI is only responsible for receiving voice commands and switching modes, without needing to continuously send motor motion commands.

5.9 App Image Transmission ​

NOTE

This lesson introduces the image transmission feature. For app download instructions, overview details, and program analyses, refer to 4.15 App Control.

5.9.1 Image Transmission Overview ​

Image transmission is a feature that streams video in real time using the camera on the WonderLLM ESP32-S3 module. Upon power-up, the module creates a self-hosted Wi-Fi hotspot. Connecting a mobile phone to this hotspot enables the app to receive camera video feeds for remote viewing.

This feature serves robotic visual observation and scene monitoring, providing a foundation for AI vision projects such as visual recognition and object tracking. It allows direct observation of camera capture feeds to verify camera hardware wiring and image acquisition routines.

5.9.5 Q&A ​

Question 1: Why is the module Wi-Fi hotspot not found after powering on following firmware flashing?

Answer:

  1. Verify that the USB power supply is stable.
  2. Verify SPI MODE settings and switch between DIO and DOUT to reflash if necessary.
  3. Check for loose connections on the camera ribbon cable.
  4. Execute ERASE again before re-flashing firmware.

Question 2: What causes a black screen without video in the app after successfully connecting to the hotspot?

Answer:

  1. Confirm that the camera ribbon cable is oriented correctly.
  2. Ensure adequate power supply current to the module.
  3. Confirm that the flashed firmware is Image_transmission.bin rather than other project firmware.
  4. Restart the module and app, then reconnect to the hotspot.

Question 3: How can video stutter and high latency be resolved?

Answer: Minimize ambient wireless interference and ensure adequate module power supply. Avoid connecting multiple devices to the module hotspot simultaneously. Lower camera resolution parameters within the program to reduce data transmission volume.
